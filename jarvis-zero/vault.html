Browser IndexedDB holds your complete game records and deduplication keys. The compatible model checkpoint also remains in local storage so the existing chessboard can play with it. Backup your data before clearing site data.

3. Private GitHub file backups

Make a private repository named jarvis-zero-private under your GitHub account. The app saves encrypted, numbered game batches plus the latest model checkpoint. Nothing goes into the public website repository.

First create the private repository and a fine-grained access token on github.com; GitHub account authorization is not embedded into this public site. The token and passphrase are not saved to browser storage. If you lose the passphrase, the encrypted backups cannot be decrypted. GitHub repos have storage and rate limits; this is scalable segmented storage, not literally unlimited capacity.

Model checkpoints use AES-256-GCM with a PBKDF2-derived key. Every game batch is an independent encrypted file. Sync is initiated by you, not silently in the background.

4. Publish your trained AI to every visitor

After importing your own games, publish model weights only to the public chessboard. No raw PGNs, account names, or encrypted personal backup files are published. Anonymous visitors automatically load the newest public checkpoint and can play without a GitHub account.

The trained weights themselves become public, so only publish when you accept that. The private game archive remains encrypted in the separate private repository. You must explicitly publish each updated checkpoint. The public AI does not learn from anonymous visitors.

JARVIS ZERO is still a lightweight AlphaZero-inspired learner. More games can improve its ability to imitate your choices, but training on your games alone cannot guarantee expert chess strength or a 1900 rating.
